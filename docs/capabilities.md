# Capabilities and limits / 能力与边界

## 保留的能力

角色与身份组合；持久会话和失效恢复；结构化结果；SQLite 运行记录；分类重试；批量派活；角色并发名额；跨进程工作目录锁；流式与文件任务记录；取消；模型表自动发现；原子名册更新。

## 后端适配器声明

这是当前适配代码的声明，不能代替对所安装 CLI 版本的实际验证。

| 后端 | 只读机制 | 结构化输出 | 可显式禁止的能力 |
|---|---|---|---|
| Claude | 工具白名单/拒绝列表 | 支持 | shell / write / network / spawn |
| Codex | 操作系统沙箱 | 支持 | network；写入还受只读沙箱约束 |
| Grok | 拒绝规则 | 尚未接入 | shell / write |
| agy | 计划模式，属于较弱约定 | 支持 | 无 |
| Pi | 工具白名单 | 尚未接入 | 无统一类别拒绝接口 |

- 本机 CLI 调用不等于模型在本地推理；CLI 可以访问远程模型服务。
- `untrusted` 是工具权限限制，不是网络防火墙或完整的攻击隔离。Claude 在这种模式下禁用额外 MCP 工具。
- 两个主力后端不能按每个目录分别提供只读挂载。资料全部只读时会压成整轮只读；有读有写则标记 soft（靠约定）。agy 的计划模式也标记 soft。
- `output_schema` 的细节验证交给支持它的后端。Fleet 自己没有实现完整 JSON Schema 验证器。
- 费用未知保留为 None；已知部分可做下界，不能当完整账单。
- 输出流提前结束时，调用方应 close 生成器，或使用 `contextlib.closing`。跨线程停止用 `RunHandle.stop()`。
- `skills` 是提示词声明，不会安装或挂载技能。共享 MCP 配置合并与后端实际可用工具仍依赖 CLI。
- 没有持久队列、后台调度、进程崩溃后的自动续跑和多人访问控制。
- 注册表、配置默认值和 CLI 协议会变化；见模型发现文档与真实调用验证说明。
